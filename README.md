# SillyTavern Link

给同一台电脑上部署的 SillyTavern 1.19.0 使用的双向接续扩展。适合“电脑玩 → 出门用手机玩 → 回来继续电脑玩”。

当前版本：**1.0.2**。支持从 GitHub 安装前端扩展，并配有不会改动 Git 仓库文件的本地安装器。非 SillyTavern 官方项目，采用 MIT 许可证。

**适用环境：Windows + SillyTavern 1.19.0。安装包含“酒馆内安装扩展”和“电脑运行配套安装程序”两步。** 同步需要服务器组件及提前加载浏览器数据，仅粘贴 GitHub 链接不能完成全部配置。其他酒馆版本会被安装器拒绝，避免覆盖未经验证的启动入口。

**游玩过程中不会自动刷新。** 当前设备持续把修改保存到你的酒馆服务器；另一设备打开时，先载入最新数据，再启动酒馆和扩展。旧页面进入待接续状态，回来点击“在此设备接着玩”即可。

## 通过 GitHub 安装

1. 在电脑酒馆中打开“扩展”→“安装扩展”。输入下面的仓库地址，**勾选“为所有用户安装 / Install for all users”**后安装。多账户模式需要管理员账户操作。

   ```text
   https://github.com/rong3742rrr-hub/sillytavern-link
   ```

2. 下载完成后，关闭酒馆服务。在电脑打开酒馆安装目录下的：

   ```text
   public/scripts/extensions/third-party/sillytavern-link
   ```

3. 双击这里的 **Install.cmd**。它会自动定位酒馆目录，安装服务器组件、启用服务器插件，并配置提前同步的启动入口。成功时会显示 `Installed SillyTavern Link 1.0.2` 和恢复副本的位置。不需要另装 Node/npm，不需要另开公网端口。
4. 重新启动酒馆服务，并刷新已经打开的酒馆页面。按下方步骤建立基准。

不要单独安装 `extension` 子文件夹，不要把本仓库整个当成服务器插件安装，也不要取消“为所有用户安装”。电脑与手机必须访问**同一台酒馆服务器、同一个酒馆账户**。

如果使用 ZIP 安装：下载并解压完整源码包，双击解压目录中的 `Install.cmd`，输入酒馆安装目录。ZIP 方式本身不支持酒馆扩展管理器里的 Git 更新；后续使用新版 ZIP 更新，或按下方流程迁移到 GitHub 安装。

## 第一次使用

1. 按上面步骤完成安装，重启一次酒馆服务。
2. 用**平时玩酒馆的电脑浏览器、原来的地址**打开酒馆。选择“这是电脑，建立同步基准”。不要换浏览器或换地址建立基准，因为本地数据库按浏览器和访问地址隔离。
3. 等电脑酒馆进入正常界面。扩展设置中能看到 **SillyTavern Link**，可点“立即保存进度”。首次同步有大量数据库或图片时会慢一些。
4. 手机通过你原来的 Sakura FRP HTTPS 地址访问，登录**同一个酒馆账户**。手机会请求电脑保存，并载入最近进度。
5. 手机上正常玩。回到电脑后，点击旧页面上的“在此设备接着玩”。只有这次主动接续才会重载；聊天过程中不会自动重载。

建立电脑基准时不需要提前打开 FRP，之后电脑上的修改会继续上传到本机酒馆服务。等要用手机远程访问时，再打开 FRP 即可。手机接续时会取最近保存的进度，并向仍在线的电脑页面请求交接。

电脑浏览器可以关闭，但远程使用期间电脑、酒馆服务和 FRP 必须保持运行。离开电脑前建议点一次“立即保存进度”，不要在显示“暂未同步”时直接关闭页面。浏览器被系统强制关闭时，尚未上传的内容无法凭空恢复到另一台设备。

若原设备留有未发送的草稿或正在生成，接续页面会等它完成。已经出门时可选择“使用已上传的进度接续”，这时使用的是服务器上最近保存的一份，原设备未上传的内容仍留在原设备。

## 更新、旧版迁移

**已经通过 GitHub 安装：**在酒馆的扩展管理器中更新本扩展；关闭酒馆服务，再运行已安装仓库里的 `Install.cmd`，然后重启酒馆并刷新页面。扩展管理器只更新仓库文件，配套安装程序负责更新服务器组件，不能省略这一步。不要另用 ZIP 覆盖 Git 安装目录。

**已经用 1.0.0 / 1.0.1 ZIP 安装，想改为 GitHub 安装：**

1. 在当前设备点“立即保存进度”，等待保存完成，再关闭酒馆服务。
2. 从旧安装包或新下载解压的源码包运行 `Uninstall.cmd`，输入酒馆目录。这会将旧程序移到恢复目录，保留同步基准、浏览器数据和账户数据。
3. 启动酒馆，按上面的 GitHub 安装步骤重新安装。配套安装时仍需关闭服务，完成后再次启动。
4. 使用原浏览器和原访问地址进入酒馆，继续使用原同步进度，**不要重新建立基准**。

旧的 ZIP 安装目录占着同名位置时，酒馆会报“已经安装”；它不能直接变成 Git 仓库。先执行上述迁移。暂时继续用 ZIP 的用户，可以直接运行新版 ZIP 里的 `Install.cmd` 更新。

## 手机备份选项

更新后，**重启电脑上的酒馆服务，再刷新手机页面**。已有电脑基准和同步进度会保留，不需要重新建立基准。

手机接续时，备份窗口有“跳过本次备份”和“以后不备份”。后者只记住当前浏览器的选择，之后仍正常双向同步。在扩展设置中重新勾选“接续前备份本设备旧数据”，即可恢复备份。

备份上传超过 45 秒会停止等待并保留“重试”和“跳过”按钮；不会让你对着一个没有出口的等待窗口。跳过会取消这次上传，然后继续载入服务器最新进度。本设备被替换的旧内容将不另存接续前备份；电脑上的冲突保护备份仍然启用。

下载、备份、载入数据库、保存校验记录会分阶段显示。大数据库分批传输和写入；同步校验记录改为摘要，不再在手机额外复制一整份数据库。数据本身仍需通过 FRP 下载，所需时间取决于大小、网络和手机性能。

## 覆盖范围

| 数据 | 处理方式 |
| --- | --- |
| 酒馆设置、当前预设参数、扩展设置、酒馆助手全局变量等 | 通过现有 settings.json 保存，按修改字段合并；阻止待接续的旧页面覆盖 |
| 已保存的预设、角色卡、世界书、聊天记录、聊天元数据、快捷回复 | 使用同一个酒馆账户的服务器文件；接续时重新加载，并保护主要保存接口 |
| 浏览器 localStorage | 自动同步，包括脚本持久设置；保留删除操作 |
| IndexedDB 数据库 | 自动发现并同步数据库结构、索引和逐条记录；支持 Blob、二进制、日期、Map、Set 等 |
| Engram 的 `Engram_*` 记忆库、小白盒本地数据库 | 纳入通用 IndexedDB 同步，不需要逐个导出；不修改这些扩展自身源码 |

当前设备约每 1.5 秒检查一次变化，IndexedDB 主页面写入完成后会加入下次上传；每 30 秒额外检查一次数据库，补上同源子页面等来源的修改。交接前会做完整检查。大数据库、网络延迟和手机后台节流会延长时间，因此这不是零延迟镜像。

**这是轮流使用两台设备的双向接续，不是两个人同时编辑同一聊天。** 同一访问地址只保留一个酒馆标签页。另一设备接续后，旧页面会阻止继续保存，避免旧数据反向覆盖新进度。

## 明确的边界

- 不复制 Cookie、登录会话、sessionStorage、内存中的未保存草稿、正在执行的请求或临时任务锁。
- 小白盒的 `xb_image_backend_jobs` 运行队列留在本设备，避免重复执行生图任务。带有独立锁/租约标记的 localStorage 项也留在本地。
- 跨域 iframe、浏览器扩展自身的数据、第三方云服务、OPFS/浏览器私有文件系统不在这套存储同步范围内。没有通用脚本能无条件读取任意插件的这些内容。
- 第三方插件若绕过酒馆标准保存接口，或必须保持专有进程状态，需要单独适配。当前机制不声称已逐项验证所有第三方插件。
- 需要支持 `indexedDB.databases()`、Web Crypto 和现代 JavaScript 的浏览器。手机请使用较新的 Chrome/Edge/Safari，并通过 HTTPS 访问；电脑 localhost 可使用 HTTP。
- 同步快照上限为 256 MB，超出会明确停止并提示，原快照不会被空数据覆盖。大量生图缓存可能达到这个上限。
- 酒馆本体更新可能还原首页的两个启动标签。更新酒馆后检查本扩展状态；本安装器针对 1.19.0，其他版本不会直接覆盖安装。

## 冲突与备份

首次以电脑为基准，接续前可选择是否备份原有浏览器数据。冲突时，首次电脑的同项修改优先；其他设备与已提交数据冲突时保留服务器版本，两份冲突内容都另存备份。断网中的设置提交保留在本地待重试，接续时不会拿旧整包设置直接覆盖服务器。

所有同步内容保存在本机酒馆账户目录下：

```
data/<账户名>/sillytavern-link/
  state.json                 # 当前同步数据，不要手动编辑
  settings-previous.json     # 上一次设置保存前的版本
  backups/                   # 首次基准、接续前快照、冲突或被阻止的提交
```

扩展面板的“查看备份”可以下载备份。插件数据备份**保留 24 小时**：服务启动时、查看/创建备份时，以及服务运行期间每分钟检查清理。服务关闭时无法执行删除，再启动后补做清理。规则覆盖本插件的首次基准备份、接续前备份、冲突备份、被阻止的提交，以及超过 24 小时的 `settings-previous.json`。

`state.json` 是当前同步数据，不会按备份规则删除。酒馆自身的备份、安装器留下的程序/配置恢复副本和手动下载到其他位置的文件也不受此清理影响。1.0.0 在浏览器中留下的无时间戳副本，会在该浏览器首次运行新版满 24 小时后清理；新版本不再创建这种重复副本。

备份可能包含聊天、API 设置或脚本内容，请按私人数据保管。需要长期留存的备份请在到期前自行下载。

## 隐私与数据去向

**本插件新增的同步请求只发往当前访问的酒馆服务器。没有作者云端、遥测、广告或公共同步服务，不会将聊天、记忆或密钥发往 GitHub。** GitHub 用于托管和下载程序源码；安装、检查更新时会连接 GitHub。

手机 → 你配置的 HTTPS / FRP 通道 → 你自己的电脑酒馆，反向同步也沿这条路径进行。使用 FRP 时数据会经过公网转发，不能将它描述为“完全离线”或“只在局域网传输”。传输保护取决于你的 HTTPS、FRP 和认证配置；本插件没有额外实现设备间端到端加密。

自动同步范围较广：脚本或其他扩展存在 localStorage / IndexedDB 里的记忆、设置、令牌或密钥，都可能随数据一同同步到同一账户的另一台设备，并写入本机同步文件。快照和备份是普通文件，没有额外进行磁盘加密。不要把同步数据目录或备份上传到公开仓库。

Sakura 和酒馆的现有认证仍然生效。同步接口就在原酒馆的 `/api/plugins/sillytavern-link/` 下，使用原来的账户和 CSRF 校验，不绕过密码、不新增公网端口。酒馆自身向模型服务发送的聊天请求，以及其他扩展原有的网络请求，仍由各自配置决定；本插件不改变它们的去向。

## 安装与卸载改变什么

安装器增加 `plugins/sillytavern-link` 和 `public/scripts/extensions/third-party/sillytavern-link` 两个目录，并把首页的两个启动标签改成先接续数据、再载入原酒馆。如果服务器插件原本关闭，会开启 `enableServerPlugins`。原来的首页和配置先备份到 `backups/sillytavern-link-install-日期时间`。

安装时不关闭或重启正在运行的酒馆。服务重启前，本次安装的页面会继续使用普通酒馆，并在扩展面板提示尚未启用同步。已打开的旧标签页也需要刷新一次。

卸载时先关闭酒馆，再运行 `Uninstall.cmd`。从 GitHub 安装目录运行时会自动定位酒馆；从解压包运行时输入酒馆路径。卸载会恢复原启动标签，把扩展文件移进可恢复备份目录；不删除浏览器数据、同步快照、聊天或其他插件，不关闭其他服务器插件。然后重启酒馆。**不要只点扩展管理器中的删除按钮**，那样不能恢复提前加载入口或移除服务器组件。卸载后账户内保留的同步文件仍需按私人数据保管。

## 测试说明

已完成独立双浏览器/不同访问地址测试，以及使用 SillyTavern 1.19.0 的独立测试副本验证。测试副本使用合成数据。版本与验证范围见 [TESTED.md](TESTED.md)。

实际手机、Sakura 公网链路和第三方插件的私人数据库尚需各用户在自身环境验证；隔离测试通过不等于所有环境都已验证。

开发者验证：安装开发依赖后运行 `npm run build`、`npm test`、`npm run test:install`、`npm run test:browser`。安装测试需要 Windows PowerShell 和 Git，所有宿主文件均在 `tests/runtime` 下临时构造。大数据回归先设置环境变量 `STLINK_HOST` 为酒馆 1.19.0 安装目录，再运行 `npm run test:mobile`；它只读取该目录的样式表，并使用隔离的 150 MB 级合成数据库。浏览器测试默认使用 Windows 上的 Microsoft Edge。运行期不依赖本项目的 node_modules。

接口参考：[酒馆前端扩展文档](https://docs.sillytavern.app/for-contributors/writing-extensions/)、[酒馆服务器插件文档](https://docs.sillytavern.app/for-contributors/server-plugins/)。
